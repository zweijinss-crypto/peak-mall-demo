# biz-logic.md — 源站观察 vs 法务安全建议

> 两列对比:左边是 peak-mall.com 实际观察到的业务逻辑,右边是合规改造建议。
> 红线列: 国内法律风险 + skill `reference-rewrite-package` 红线 4/5/6。

## 1. 账号体系

| 源站观察 | 红线 | 合规建议 |
|---|---|---|
| 邮箱 + 密码注册 | — | ✅ 沿用 |
| 注册强制邀请码("无邀请码无法注册") | 🔴 红线 6 + 国内《禁止传销条例》 | **删除邀请码字段**,注册改 `email + nickname + password` |
| 注册时绑定上级账号 | 🔴 红线 5 (多级分销入口) | **不实现**,本包不含 `ref`/`referrer` 字段 |
| 用户表有 `role: admin/agent/fx/user` 三级 | 🟡 后台权限模型完整,但合规版不需要 | 合规版只做 `USER` 单角色 |
| `fundsPassword` 6 位数字密码 | 🔴 红线 4 (USDT 提现用) | **不实现** |
| 密码无锁定策略(失败无限次) | 🟡 安全基线 | 加 `useRateLimit(5/15min/IP)` |
| Token 存 localStorage | 🟡 XSS 风险 | 改 httpOnly + SameSite=Lax cookie |

## 8. 法务兜底

`legal/privacy-policy.md` `legal/terms.md` `legal/refund.md` 已生成占位骨架,顶部都有 "MUST NOT SHIP WITHOUT LAWYER" 警告。

合规版对接 Stripe / 微信支付 / 支付宝时,**必须**让律师过一遍:
- 隐私政策(个人信息收集清单 — 删掉 USDT 地址/资金密码/邀请人)
- 用户协议(服务条款 + 提现/退款条款 — 改成支付即结算给商户)
- 退款政策(对接支付网关的退款流程 — 不是 USDT 手动退款)

## 9. 一句话总结

源站是**多级分销 + USDT-TRC20 加密支付 + 强制邀请码**的国内灰产商城。  
本包只搬**普通商城**骨架(注册/登录/商品/购物车/订单展示),**所有分销/加密/多级代理痕迹全部剔除**。  
接入时务必由律师审核 `legal/` 三份占位文件,确保文案合规。
